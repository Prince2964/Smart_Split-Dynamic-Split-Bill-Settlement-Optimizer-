# SplitSmart: WhatsApp invitations and deployment checklist

## WhatsApp invite flow implemented in this update
- The group invite modal no longer asks for a name or email.
- The admin can create a time-limited (7 day) reusable invite link.
- The link can be shared on WhatsApp or copied manually.
- The invite URL is generated by the backend from `FRONTEND_URL`; invite links must point to the deployed frontend for other people to open them.
- Link invitations are reusable until expiry. Only authenticated users can join, and the backend checks the invitation token.

## Deploy the backend on Render
1. Push this project to GitHub. Ensure `backend/package.json` and `backend/server.js` are committed. Do not commit `.env`.
2. In Render create a **Web Service** connected to the repository.
3. If frontend and backend are in the same repository, set **Root Directory** to `backend`.
4. Build command: `npm install`. Start command: `npm start` (or `node server.js`).
5. Add these environment variables in Render using the exact names from your local backend `.env`: `MONGODB_URI`, `JWT_SECRET`, `FRONTEND_URL`. Keep `RESEND_API_KEY` and `RESEND_FROM_EMAIL` only if you intend to re-enable email later. `PORT` is normally supplied by Render; server code already uses `process.env.PORT || 3000`.
6. Set `FRONTEND_URL` to the exact deployed Vercel frontend origin, e.g. `https://your-project.vercel.app` (no `invitation.html` suffix).
7. Wait for the Render service to deploy and copy its generated URL.
8. In `js/config.js`, replace the local default `http://localhost:3000/api` with `https://YOUR-RENDER-SERVICE.onrender.com/api`. Commit and push this change; Vercel will redeploy.
9. Open the Render backend root URL. It should show `SplitSmart Backend is running!`. Then test login, group loading, expense creation, and invitation link creation from the deployed Vercel site.

## MongoDB Atlas
- In Atlas Network Access, allow Render to connect. For a short test, a broad `0.0.0.0/0` rule may be used only if you understand it permits access from any IP; use strong database credentials and least-privilege DB users. Prefer tighter access controls where available.
- Keep the MongoDB URI private. Never paste `.env` or API secrets into chat or commit them.

## Invitation security / behavior
- Share links expire after 7 days.
- Anyone who receives a link can attempt to join, but must create/sign into an account. Treat the link like a key: only share it with intended group members.
- Do not deploy while `js/config.js` still points at localhost; online visitors cannot reach your laptop.

## Checks performed in this source update
- JavaScript syntax checks should be run with `node --check js/group-page.js` and `node --check backend/server.js`.
- Live API, Vercel, Render, and Atlas behavior still requires deployment and testing in your own accounts; this archive does not claim those external services have been deployed.
